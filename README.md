# PRISM — Interactive Chunk Playground

*Learn. Experiment. Build.*

**An interactive, self-paced 45-minute lesson that teaches beginners how _text chunking and document processing_ power Retrieval-Augmented Generation (RAG).**

Built for the **Instructional Designer Intern (AI Courses) — Kalvium** assessment.
Selected topic: **#5 · Text Chunking and Document Processing for RAG.**

> Runs 100% in the browser. No backend, no API keys, no paid services, no build step.
> **Bring your own document:** upload or drop a `.txt`, `.md`, `.pdf`, `.docx` or `.html` file (or paste text). PRISM extracts and cleans the text in the browser, then lets you chunk it and run the RAG simulation on it. Try the files in [`samples/`](samples/).

Double-click `index.html`. Everything works from the file system.

## The learning journey (45 minutes)

| # | Module | Time | What the learner does |
|---|---|---|---|
| 0 | Welcome & learning goals | 2 min | Reads 7 objectives and how to use the lesson |
| 1 | The problem & RAG | 4 min | Compares "send the whole handbook" vs "retrieve relevant parts"; explores a clickable 7-stage RAG pipeline |
| 2 | What is text chunking? | 6 min | Learns 4 key terms, chunks a paragraph live, compares fixed vs sentence-based output |
| 3 | Chunk size & overlap ★ | 8 min | Turns a size dial, toggles overlap on a boundary problem, measures characters / words / tokens |
| 4 | The Chunking Lab ★ | 8 min | Edits, pastes or **uploads their own document**, tunes strategy / size / overlap, reads live stats + feedback, compares two configurations |
| 5 | RAG retrieval simulation | 6 min | Asks questions about the sample handbook **or their own document** and watches chunking → keywords → scoring → retrieval → answer |
| 6 | Engineer challenge | 4 min | Chooses settings for a policy document, runs 3 retrieval tests, justifies the choice, gets feedback |
| 7 | Knowledge check | 5 min | 6 application-level MCQs with instant feedback, explanations, score, retake |
| 8 | Real-world apps & wrap-up | 2 min | 5 real use cases, end-to-end architecture, real code, takeaways, completion summary |
| | **Total** | **45 min** | |

The brief's suggested timings (5 + 7 + 10 + 10 + 7 + 6 = 45) left no time for the welcome, challenge and conclusion, so they were rebalanced proportionally to keep the total at exactly 45 minutes.

### Learning objectives
By the end, learners can:
1. Explain why large documents must be processed before being used in RAG.
2. Describe text extraction and document preprocessing.
3. Explain text chunking and its purpose.
4. Differentiate fixed-size and sentence-based (structure-aware) chunking.
5. Reason about chunk size and chunk overlap trade-offs.
6. Experiment with chunking parameters and interpret results.
7. Explain how chunks are retrieved in real AI applications.

### Instructional design choices
- **Problem first:** every module opens with a concrete scenario (a 200-page university handbook) before introducing terms.
- **One idea at a time:** each technical term is defined in one line when it first appears.
- **Learn → see → do:** explanation → live visual generated by the real engine → learner-controlled experiment.
- **Feedback, not verdicts:** the Lab, Compare panel and Challenge describe trade-offs. No configuration is ever labelled "best".
- **Honest simulation:** anything not real (embeddings, vector DB, LLM) is clearly labelled as conceptual or simulated.
- **Progress & autonomy:** sticky nav, lesson map, 45-minute timeline, per-module "Done · Next", completion summary, and progress saved in the browser.
- **Play that rewards understanding:** XP and badges are tied to meaningful experiments (using overlap, finding a fragmented answer, passing retrieval tests), so the game loop reinforces the learning goals. Calm mode keeps it accessible.

## Features

### Learn while playing (`js/fun.js`, `css/fun.css`)
- **Chunky the mascot:** a small document character that greets each module with a tip, gives hints when tapped, and reacts to what the learner does. It is happy on correct answers, sad on wrong ones, shocked when an answer gets fragmented, and cheers on achievements.
- **XP and 5 levels** (Chunk Rookie → RAG Master): +20 XP per module, +10 per first-time correct quiz answer, +25 per badge.
- **10 badges for real learning actions**, not clicks. Examples: *Bridge Builder* (use overlap), *Sentence Surgeon* (sentence chunking with zero mid-sentence cuts), *Fragment Finder* (discover an answer sliced by bad chunking), *Doc Engineer* (pass all 3 challenge tests).
- **"See it happen" animations:**
  - The paragraph physically slices into chunk cards (FLIP animation from each sentence's position).
  - "▶ Play the pipeline" sends a question through all 7 RAG stages.
  - Score bars rise for every chunk in the RAG simulation.
  - Stat numbers count up and flash when they change.
  - Quiz options bounce or shake.
- **Celebrations:** confetti bursts, floating "+XP", badge and level-up pop-ups, and confetti rain on a perfect quiz or full completion.
- **Transitions:** scroll-reveal with staggered cards, squishy clay buttons, slider value pops, and a floating hero.
- **Calm mode** (lesson map → toggle) switches all motion, the mascot and confetti off. It is on by default when the operating system requests reduced motion. Content and features are identical in both modes.

### Chunking engine (`js/chunking.js`)
- **Fixed-size word chunking:** with `N` words, size `C`, overlap `O`, and step `S = C − O`, chunk *k* starts at `k·S`. It stops as soon as a chunk reaches the end, so there is never an empty or fully duplicated trailing chunk. Overlap is clamped to `C − 1`, so `S ≥ 1` and the loop always terminates.
- **Sentence-based (structure-aware) chunking:** packs whole sentences up to `C` words and never merges across paragraphs. Overlap carries whole trailing sentences (≤ `O` words). A single sentence longer than `C` is split with fixed windows, because there is no other way to respect the limit.
- Every chunk is a word range `[start, end)`, so overlap with the previous chunk is exact: `prev.end − start`.
- Stats are computed from the actual output: total words, chunk count, average / min / max size, redundant words, redundancy %, and chunks cut mid-sentence.

### Bring your own document (`js/docloader.js`)
- **Text extraction in the browser.** TXT/MD/CSV/JSON are read directly. HTML has scripts, styles, nav and footer removed, and block elements become paragraphs. PDF is extracted with pdf.js, and paragraphs are rebuilt from the vertical gaps between lines. DOCX is extracted with mammoth.js. The PDF and DOCX libraries are loaded from cdnjs only when needed, so the rest of the site works offline.
- **Preprocessing with a visible report:** removes page-number lines, repairs hyphenated line breaks, joins wrapped lines, strips invisible characters, collapses whitespace, and keeps paragraphs. The learner sees exactly what was cleaned.
- **Guards:** 10 MB file limit, 50,000-word cap (with a notice), and friendly errors for unsupported types, legacy `.doc`, empty files and scanned PDFs (which would need OCR).
- **Privacy:** files are read with the browser's File API and never leave the device.
- In the RAG simulation, suggested questions for an uploaded document come from its most frequent keywords, not from a fixed list.
- Large documents render a capped number of chunk cards (all chunks are still counted and searched).

### Retrieval simulator (`js/retrieval.js`) — clearly labelled as a simulation
- Removes stopwords and applies light stemming. A small synonym list is shown on screen, which demonstrates why keyword search needs help and embeddings don't.
- TF-IDF-style scoring: `Σ (1 + ln tf) × idf` over the query terms.
- **Extractive "answer":** sentences are copied word-for-word from the retrieved chunks. No LLM is involved, so bad chunking visibly produces fragments.
- **Fragmentation check:** detects when the best-matching sentence is split across chunks and explains why.

### UI
- Claymorphism + minimal editorial design system using the brief's palette (Warm Ivory, Deep Teal, Coral, Dark Forest).
- Manrope / Inter / JetBrains Mono.
- Responsive across desktop, tablet and phone. Keyboard-friendly segmented controls and quiz (arrow keys). Visible focus rings, a skip link, `aria-live` feedback, and `prefers-reduced-motion` support.

## What is real and what is simulated

| Pipeline stage | In PRISM |
|---|---|
| Document upload | **Working** (upload, drag & drop, or paste) |
| Text extraction | **Working** for TXT, MD, HTML, PDF (text-based) and DOCX. Scanned PDFs (OCR) are not supported |
| Preprocessing | **Working** (page numbers, hyphenation, wrapped lines, whitespace) |
| Chunking (fixed + sentence-based) | **Working**, unit-tested |
| Embedding generation / vector DB | Conceptual only |
| Retrieval | **Simulated** with keyword TF-IDF scoring |
| LLM response | **Simulated**: extractive sentences, no model |

Word counts are a teaching simplification. Production systems measure chunk size in **tokens** with the model's tokenizer. The token estimate shown (characters ÷ 4) is a rule of thumb.

## Why "PRISM"?
A prism splits one beam of light into separate bands, just as chunking splits one document into separate pieces. Each band can be examined on its own, and the logo shows exactly that.
